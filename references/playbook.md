## 2. 逐步固定方法

### step1-① 主图 5 张

```
找法：遍历 input[type=file][accept*=image]
      邻近文本含「商品正面图|上传主图」→ front
      邻近文本含「上传辅助图」        → extra（取 4 个）
动作：front.setInputFiles(第1张) → 依次 extra[k].setInputFiles(第k+1张)
```

- 抖店只有 **5 个槽位**，素材包超出的由 `build_product.py` 截到 5 张并告知
- 上传后**会弹出图片预览浮层**，必须 `dismissOverlays(page)` 才能继续点

### step1-② 标题

- **禁止用 Playwright `click` + `fill`**（浮层拦指针会超时），改用原生 setter
- ⚠️ **placeholder 会随页面状态变**，不能写死数字：
  | 页面状态 | placeholder |
  |---|---|
  | 全新第一步（刚进创建页） | `请输入2-60个字符（1-30个汉字）` |
  | 有草稿 / 第二步 | `请输入15-60个字符（8-30个汉字）` |
  正确找法：遍历 `input`，取 placeholder **同时含「个字符」与「汉字」** 的那个
  （`setTitle` 已按此实现；这是 2026-09-30 端到端首跑失败的真因——只匹配 `15-60个字符` → `title_input_not_found`）
- ⚠️ **全新第一步里「商品类目」区是异步渲染的**：给完主图+标题、AI 识别完成后才出现。
  选类目前必须先 `waitForCategorySection(page)`（轮询等「手动选择类目」入口，最多 45s），否则 `manual_picker_entry_not_found`
- 读回 `.value` 必须等于目标串
- 标题上限：**8-30 汉字 / 15-60 字符**；GPVC-001 用 28 汉字 = 显示 `58/60`，几乎顶格
- 页面上的「AI 推荐标题 + 立即使用」**不要点**（实测推荐与商品无关）

### step1-③ 类目

```
1. 点 text=手动选择类目  → 打开「选择类目」弹窗
2. 搜索框：input[placeholder*="类目关键词搜索"]  → fill(关键词)
3. 结果项：div[class*=resultItem]，文本是**无分隔符拼接**的完整路径（如「家装建材墙面材料墙纸」）
4. ⚠️ 必须用 evaluate 内原生 el.click() —— Playwright click 会被
   div.ant-scrolling-effect#__ffa-goods-popup-container__ 拦指针
5. 弹窗底部「确认」按钮 → 原生 click
6. 读回主表单「商品类目」文本（截到「修改」之前）+ 「下一步」是否 enabled
```

**匹配口径**：归一化（去空格与 `>`）后**全等**优先，其次 `endsWith`；禁止 `includes` 模糊命中。

### step1-④ 下一步

`Array.from(document.querySelectorAll('button')).find(b => b.innerText.trim() === '下一步')` → 原生 click。
类目未确认时它是 `disabled`。

### step2-⑤ 属性（重点）

**控件定位**：属性标签叶子 → **上溯第 5 层** = form item 容器。

| 类型 | 展开后的下拉 | 填充 |
|---|---|---|
| 单选 | `div.ecom-g-select-dropdown.auto-dropdown-id-<属性名>` | 原生 click 选项 |
| **多选** | `div.ecom-g-select-dropdown.styles_multiSelectDropdown`（无 per-属性 id） | 同上，同一时刻只开一个 |
| **可搜索**（品牌） | 同单选 | 先用**原生 setter** 写入关键词（否则不过滤），再点选项 |
| 文本 | 无下拉 | 容器内 `input.ecom-g-input[placeholder=请输入]` 直填 |

**必须幂等**：先 `readAttr(label)`，与目标一致就跳过。
**多选重复点同一项会取消**（实测把已设好的「适用空间=客厅」点空）。

**墙纸类目属性清单**（GPVC-001 实测）：
重要属性：品牌★ / 适用场景 / 适用对象 / 墙纸规格 / 计价单位 / 面层工艺 / 风格 / 图案 / 有无图案 / 同城服务 / 壁画材质 / **厚度(文本)** / **每卷长度(m)(文本)** / **每卷宽度(m)(文本)**
其他属性：材质★ / 类型 / 产地 / 是否可定制 / 辅材套餐 / 适用空间 / 上市时间

**属性值不在下拉里怎么办**：下拉底部有 `+新建<属性名>`，可现场新建（`flow.addAttrOption(page, label, value)`）。

```
打开属性下拉 → 真实点击「+新建<属性名>」→ 出现 input[placeholder="请输入自定义属性"]
→ keyboard.type 输入值 → 点 img[alt="确认"] → 读回该属性 == 新值
```

四个实测要点（2026-10-05 隔离验证）：
1. **不需要先在搜索框输入** —— 编辑器出现时本来就是空的。（我一开始以为必须先输入：那只是「输入后列表被过滤变短」的副作用，掩盖了下面的真因。）
2. 选择器**必须限定在本属性自己的下拉内**：`.ecom-g-select-dropdown.auto-dropdown-id-<属性名> span.styles_newSKU__tOwhj`。
   页面上**每个属性都有一个同名入口**，其余下拉是 `display:none` → 用 `.first()` 会选中隐藏的那个。
3. 必须用 **Playwright 真实点击**：原生 `dispatchEvent` 触发不了 React。真实点击还会自动滚动到位 ——
   该入口在**虚拟列表末尾**，不输入时实测 `rect.y = -1334`（在可视区外）。
4. 编辑器输入框必须 `keyboard.type` 真实输入（setter 改值不进 React state，点确认会被当空值）。

**⚠️ 新建的值只在当前草稿里有效**（实测：新建后本草稿能选中、下拉变成 49 项；换新草稿又回到 48 项、没有该值）。
它**不会写回店铺类目选项集**，所以每条新草稿都要重来一次 —— 这就是 `run_listing.js` 里
`DY_CREATE_ATTR_MISSING=1`（`fillAttributes` 的 `createMissing`）自动处理的事：值不在下拉里就新建并选中。

**多值属性**（如 `材质 = PVC / 无纺布`）会**逐个点选**（`fillAttributes` 已支持数组），
读回要求全部值都在；多值属性也会出现在日志里。

**允许值来源**：素材包「选项_dy」sheet（风格 116 项、产地 225 项、面层工艺 18 项…）。
写值前 `read_excel.py` 已做校验；不在表里的值会给 `attr_warnings`，**要告知用户，不要静默换值**。

### step2-⑥ 详情图

> **模板可能没有「商品详情」字段**（实测「墙贴」cateId 1000005101 的 73 列模板就没有）：
> 此时商详图不在 Excel 里，由 skill 自己带 —— `build_product.py --detail-dir <目录>`，
> 或把图放素材目录下的 `商品详情/` / `详情图/` / `02_详情图/`（builder 会先在 assets 找、再在父目录找）。
> 实测 PE3：39 张商详图全部满足宽 620-1290px。


```
find: input[type=file][multiple=true][accept*=image] 且邻近文本 == "上传图片"
（注意：早期按 multiple=false 找会找不到）
上传后读回：商详图片 N/50
幂等：count >= 目标张数就跳过
```

约束：**宽 620-1290px、<5MB**（`build_product.py` 已预检）。

### step2-⑦ 规格 + SKU（Excel 智能识别）

> ⚠️ **规格值里不要用 `（…）`**：识别会把括号当补充说明剥掉 → 值塌陷
> （`白色（2.0版/标准遮丑）` → `白色`；12 个尺寸值塌成 4 个，36 SKU 变 12）。
> 用 `-` 分隔：`白色-2.0版-标准遮丑`。
>
> ⚠️ **成功判定看文案**：「完成识别并填入规格选项」+「价格填写进度」，别只看可见行数（虚拟滚动可能是 0）。

```
1. 上传 input[type=file][accept*=".xlsx"]  ← dy_spec.xlsx（5 列：规格1/规格2/售卖价/库存/规格编码）
2. 点「智能识别」（未上传文件时 disabled，class 带 style_identifyButtonDisabled__）
3. 进度文案：正在获取您上传的内容 → 已识别完成您上传的信息 → 已为您生成规格信息 → 正在为您优化规格层级
4. 完成后助手区变「完成识别并填入规格选项 / 删除 / 重新上传」
5. 生成的规格表表头：颜色 | 款式 | *价格 | *现货库存 | SKUID | 商家编码 | 条形码 | 预览图 | SKU状态
```

- **表头按语义自动映射**：售卖价→价格、库存→现货库存、规格编码→商家编码
- 汇总价区间自动算（如 `9.9~45.9`）填进「售卖价」
- **幂等**：已识别过（出现「完成识别并填入规格选项」或规格表已有行）就跳过
- 输入框可能不在页面上，需先点「重新上传」或「删除」把上传卡叫回来
- SKU 表是**虚拟渲染**（DOM 里只有部分行），统计行数不能只数 `tbody tr`

### step2-⑧ 规格图（挂在规格值上）

```
1. 点「批量上传规格图」→ 直接唤起文件选择器（无弹窗）
   定位：input[type=file][multiple=true][accept*=image] 且邻近文本含「批量上传规格图」
2. 上传后打开抽屉「规格图设置」，提示「请将已上传的规格图与规格值相匹配」
3. 抽屉表格：规格图 | 规格值 | 操作
   - **行序 = 上传顺序**（已用文件字节数核对）
   - 每行的规格值下拉 = div.ecom-g-select-dropdown.sp-multiple-dropdown，**多选**
   - 选项 = 该商品的规格值；留空 →「未选择默认生成新规格」
4. 逐行原生 click 选项 → 读回该行已选 == 目标
5. 点「确定」→ 抽屉关闭
```

**映射策略**：图片按**规格值顺序**上传即可让行序与规格值一一对应，无需文件名匹配。
GPVC-001：8 色 → 8 张，每张对应一个颜色规格值（比拼多多逐 SKU 行传图省事）。

幂等：规格值旁已有 60-120px 方图缩略图就跳过。

## 3. 与拼多多的关键差异（迁移时必看）

| 维度 | 拼多多 | 抖店 |
|---|---|---|
| 流程 | 类目页 → 表单（1 步） | **第一步(主图+标题+类目) → 第二步(全表单)** |
| 主图 | 轮播 10 张 | **1 正面图 + 4 辅助图 = 5** |
| 标题 | ≤30 汉字 | 8-30 汉字 / 15-60 字符（**汉字算 2**） |
| 类目 | 搜索 + 全路径 | AI 推荐 + 手动弹窗（结果文本无分隔符） |
| 类目属性 | 各平台独立属性集 | **「墙纸」属性集：14 重要 + 7 其他，字段名完全不同** |
| 规格维度 | 最多 2 维 | **最多 3 维** |
| 规格/SKU 建法 | 逐行 setter（虚拟滚动 + sticky） | **可走 Excel 智能识别**，大批量更快更稳 |
| SKU 图 | 逐 SKU 行传预览图 | **规格图挂规格值**（按规格值传，数量少得多） |
| 价格 | 拼单价/单买价/参考价 | **售卖价/参考价**（无拼单价） |
| 详情图 | ≤50 张 | ≤50 张，**额外要求宽 620-1290px** |
| 提交 | `goods_add/success` | 「发布商品」（本技能不点） |

## 4. 排错表

| 现象 | 根因 / 处理 |
|---|---|
| Playwright click 超时、`intercepts pointer events` | 浮层（主图预览/弹窗）拦指针 → `dismissOverlays` 或原生 `el.click()` |
| `next_not_found` / `next_disabled` | 在第二步，或类目没确认 |
| `front_slot_not_found`（slots 空） | 在第二步执行了第一步的动作 → 先用 `detectStep` 判断 |
| `connectOverCDP` 卡 ws connected | 某标签页 CDP 无响应 → `closeHungTabs(port)` |
| 多选属性被点空 | 缺幂等判断 → 先 `readAttr` 比对，一致即跳过 |
| 详情图/规格图张数翻倍 | 幂等判断被绕过（用了 `force: true`） |
| 品牌搜不出来 | 没用原生 setter 触发搜索；或该品牌未在抖店注册（需申请/用无品牌） |
| 从第二步续填报 `step2_draft_mismatch` | 当前标签页是别的草稿（类目/标题不符）→ 换到正确草稿，或设 `DY_ALLOW_STEP2_MISMATCH=1` |
| `fails` 出现 `spec_pairing:*` / `spec_images_not_paired` | 规格图没配对（多为 Excel 文件名与素材目录不一致）→ 看 build 阶段告警 |
| `value_not_in_options` | 值不在「选项_dy」里；选近值并告知用户，或问过用户后用 `flow.addAttrOption` 新建；**不要静默换值** |
| 点「+新建<属性>」报 `Element is not visible` | 用 `.first()` 选中了**别的属性**（隐藏）的同名入口 → 选择器限定 `.ecom-g-select-dropdown.auto-dropdown-id-<属性名>` |
| 新建后点确认没生效 | 编辑器里用 setter 写的值不进 React state → 必须 `keyboard.type` 真实输入 |
| 规格识别按钮点不动 | 还没上传 xlsx（class 带 `Disabled`） |
| 规格图抽屉分配失败 | 下拉没开（要等 ~1.3s）或规格值不存在 |
| 规格图抽屉 12 行全 `value_not_found` | ① 出图维度不在规格类型1（只有第一组能挂图）；② 规格值里的括号被剥掉导致值不匹配 |
| 规格值被截断/塌陷（如 12 个变 4 个） | 规格值里用了 `（…）` → 改用 `-` |
| 多选属性点不中（如「适用空间=卧室」） | 虚拟树下拉首屏只渲染约 10 项 → `pickAttr` 已内置「滚动查找」；偶发失败会自动重试 2 轮 |
| `手动选择类目` 点击超时 `element is not stable` | AI 推荐区持续重渲染 → 已改原生 `el.click()` + 轮询 |
| 规格图只有第 1 行成功、其余 `got:""` | 抽屉行按「含 select 的行」定位会漂移 → 改为按**图片顺序**定位 |
| 参考价填不进 | **它不是「填不进」，是默认不开**：`[attr-field-id="参考价"]` 行里只有一个开关（`role="switch"`、默认关），关着整组不渲染、不卡必填（墙纸类目实测 `必填 100%` / 报错 `[]`）。**用户已定：不开、不填、不必发问**；只有用户主动要求开某条链接时才问「凭证类型 + 凭证图 + 金额（≥售卖价）」。详见 RECON.md §6.5 |
| `商详图 = 0` | 该类目模板没有「商品详情」字段 → 用 `--detail-dir` 指定商详图目录 |
| 商家编码重复（同色同长共码） | 抖店不强制唯一，正常；`checkSkuTable` 按集合比对 |

## 5. 实测数据（GPVC-001，16 SKU）

| 阶段 | 耗时 |
|---|---|
| 主图 5 张 + 标题 | ~14s |
| 类目搜索 + 确认 + 下一步 | ~20s |
| 属性 14 项 | ~25s |
| 详情图 8 张 | ~8s |
| 规格 Excel 智能识别 | ~25s |
| 规格图 8 张 + 分配 | ~25s |
| 发货/状态 radio | ~1s |
| 填写检查 | ~4s |
| **合计** | 约 2 分钟（幂等重跑仅 ~7s） |

对比：拼多多 16 SKU 约 1.5 分钟，但**抖店走 Excel 识别 + 规格图挂规格值**，行数越多优势越明显
（拼多多 72 SKU 填值就要 ~100s + 预览图 ~79s，抖店这两步都可批量化）。
