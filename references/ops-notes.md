# 运维笔记：事故复盘 + 改代码前后的必做动作

> 这份是**给以后改这个技能的人（或 agent）看的**。教训都来自本技能的真实事故，
> 不是通用建议。逐步操作手册在 `playbook.md`，门禁在 `SKILL.md`，完整交接在 `HANDOVER.md`。

---

## 一、改代码前的三条铁律

1. **先备份**。要动 `scripts/dy_flow.js`（1400+ 行）这类大文件前，先复制一份：
   ```powershell
   Copy-Item "$skillRoot\scripts\dy_flow.js" "$skillRoot\_backup\dy_flow.js.bak" -Force
   ```
   `_backup/` 里的 `*.bak` **给使用者可以直接忽略**；它只是改坏时的退路。
   （本项目在 PDD 那边曾因没有备份而**误删 35KB 代码**，所以这条是硬要求。）

2. **别用「读进来→改字符串→写回去」的方式大段替换**。我这么干过一次，拼接时把
   `\(` 写进了文件，`node --check` 直接报 `SyntaxError`；更早还因为 PowerShell 的
   `@"..."@` **双引号 here-string 会展开 `$变量`**，把文档里的 `$skillRoot`/`$DyEnv`
   替换成了空串（写进 SKILL.md 才发现）。
   → 要改大段，**优先用 Edit 工具按精确文本替换**；非要用脚本，就把 python 写进
   **临时 .py 文件再执行**（不要塞进 `-c` 参数，PowerShell 会吃掉引号）。

3. **动手前断言边界**：切片替换时先打印 `start/end` 行号和首末行，确认切的是你想切的那段。

## 二、改完代码后必须做的四件事

```powershell
# 1) 语法
& $DyEnv.node -e "require('$skillRoot/scripts/dy_flow.js')"     # 顺带验证 require 能过
node --check <file>

# 2) 纯逻辑单测（1 秒）
& $DyEnv.python "$skillRoot\scripts\test_dy_logic.py"

# 3) 导出点名（改了导出表时）
& $DyEnv.node -e "const f=require('.../dy_flow.js'); ['scanSkuTableFull','checkSkuTable',...].forEach(n=>console.log(n, typeof f[n]))"

# 4) 真跑一遍（改了 DOM 层就走一次最小单：16 SKU 的 GPVC-001 约 2.3 分钟）
```

**教训**：这个项目里最容易漏的是**新增校验/新分支后没人调用它**。PDD 那边就出过
「`validateForm` 新增了 `main_images` 项，但调用方没把数据传进去 → 整项被静默跳过，
`allPass` 照样 true」。所以新增读回项后，**必须确认调用方真的把数据传进来了**。

## 三、事故复盘（按发现顺序）

### A. `fails=[]` 但表单里有必填项没填（MZB-007）

- **症状**：`fails=[]`、`必填项进度 100%`，但报错里有一个「错误」、`价格填写进度 98%`。
- **真相**：72 行里助手漏填了 1 行价格；`checkSkuTable` 只看**可见十几行**，那行在窗口外；
  而失败汇总**从来没看 `st.errs`** → 半成品被判全绿。
- **已修**：① ⑦b `fillMissingSkuCells` 全表找空值按编码补齐；② `fails` 新增 `form_errors`
  （`errs` 非空即失败）与 `sku_cells_missing`；③ ⑩b 改为**全表**核对。

### B. 守卫读到的值是空的 → 守卫形同虚设（ZDT-002）

- **症状**：加了「出图组不匹配就中止」的守卫，但坏分支上照样点了「确定」，草稿被弄脏
  （尺码组冒出一批「有图但值为空」的幻影行，价格进度 100% → 28%）。
- **真相**：守卫读「该组有哪些值」用的是「在组块里找输入框」——**读出来永远是空数组**，
  条件 `on.values.length && ...` 恒不成立。改成按 `placeholder == "请输入<组名>"` 归属后才真生效。
- **教训**：**守卫的条件本身也要有证据**。加完守卫要**在坏分支上验证它真的拦住了**
  （我就是拿一条已损坏的草稿当样本验的）。

### C. 组名不是固定的 → 按名字找组全落空（GPVC-001 之后 · 猫抓板）

- **症状**：4 轮全挂在 `no_group_with_image_switch`。
- **真相**：猫抓板类目里助手把两个规格组命名成「**颜色**」「**规格**」，而所有代码都写死了
  `/^规格类型\d$/` 与 `请输入规格类型N`。
- **已修**：判据全改**结构性** —— 组头 = 含叶子文本「添加规格图」的那一行；
  **带图组 = 组头行里含「批量上传规格图」的那一组**；组的值 = `请输入<组名>`。

### D. 关残留下拉用了 Escape，把抽屉一起关了（ZDT-002 第 4 轮）

- **症状**：⑧ 只有第 1 行成功、2-9 行 `clicked:false`，整轮半残。
- **真相**：`closeDropdowns()` 用 Escape 关弹层，Escape 有时会连**抽屉**一起关掉。
- **已修**：改成「点抽屉内部（`th`）」+ 每行前 `drawerAlive()` 探测。

### E. 点 trigger 是「切换」不是「打开」（ZDT-002 首轮）

- **症状**：多值属性只填进第一个值（`功能=防滑`，第二个「耐磨耐踩」永远选不上）。
- **真相**：多值循环里二次调用 `openAttr` 又点了一次 trigger，把刚打开的下拉**关掉了**。
- **已修**：`openAttr` 按 `aria-expanded === 'true'` 做幂等。
- **同源的第二处**：读回多选属性只取了第一个 `selection-item` → 明明填进去了却判失败并反复重试。
  已改成读全部、` / ` 连接。

### F. 半残赋值被落进 SKU 表（ZDT-002）

- **症状**：抽屉里「图片对上了、值却是空的」提交后，草稿多出幻影规格值，价格进度 100% → 76%/28%。
- **已修**：**没全部行成功就绝不点「确定」**。
- **教训**：**宁可失败重来，也不要把草稿弄脏** —— 重跑一次约 2-3 分钟，在坏稿上救更贵。

### G. 只读侦察把已填表单冲掉（PDD 侧 · GPVC-001，本技能同源风险）

- **症状**：读回脚本 `connectShop` 拿到 page 后 `goto` 别的 URL → 已填草稿被导航走，计数错乱。
- **铁律**：**任何读回/侦察都在当前页原地 `page.evaluate`**；要开新页用
  `browser.contexts()[0].newPage()`，**不要用 `connectShop` 去拿那个 page**。

### H. 把「手推」当事实写进文档（本轮 · 由单测抓出）

- **症状**：单测断言「strip 会把同色三档撞成 1 个值」→ 实际 3 个。
- **真相**：`白色#【10倍非凡品质】5.0标准款` 剥完是 `白色#5.0标准款`，**括号后面还有区分文字**，
  不会撞。我当初是**手推的、没实测**，还把这个错说法抄进了 `SKILL.md`/`HANDOVER.md`/`tests/README.md`。
- **已修**：文档三处更正 + 三种情形（PE3 会撞 / GPE-002 不撞 / GPVC-001 前缀全同）固化成单测断言。
- **教训**：**「会/不会塌陷」这种事必须实测**（数一下值数），别推。单测就是干这个的。

### I. 把规格值管理区的行当成 SKU 行（扫表工具第一版）

- **症状**：扫表报「缺价格的行」一堆，实际那些是规格值管理区的「值行」。
- **真相**：它们也用 `tr.ecom-g-table-row`，但没有价格/库存输入框。
- **已修**：按「有没有价格/库存输入框」过滤真实 SKU 行。

### J. `writeCell` 读了参数却没传（补漏第一版）

- **症状**：补漏找到了行，但 `didPrice/didStock` 都是 false → 静默什么都没写。
- **真相**：函数里读 `a.needPrice`，调用时没传 → undefined 恒假。
- **教训**：这是**我自己写的低级错**，且表现是「静默不干活」而不是报错 ——
  所以函数**写完必须读回验证**（`fillMissingSkuCells` 现在就带 readback 校验）。

### K. 一行 python 把两个 .ps1 清空了（自我截断）★

- **我干的**：想给两个 `.ps1` 补 UTF-8 BOM，写了这么一行：
  ```python
  [io.open(p,'w',encoding='utf-8-sig',newline='').write(io.open(p,encoding='utf-8').read()) for p in FILES]
  ```
- **真相**：Python **从左到右求值** —— `io.open(p,'w',...)` **先执行**，文件当场被**截断成 0 字节**，
  之后 `.read()` 读到的是空串 → 写回空文件。`resolve_env.ps1` 和 `preflight.ps1` 各剩 3 字节（只剩 BOM）。
- **恢复**：`resolve_env.ps1` 靠本会话早先**完整读过一次**的原文重建（+ PDD 侧的 `pdd-product-listing/scripts/resolve_env.ps1`
  是同构脚本，可作交叉核对）；`preflight.ps1` 是刚写的、内容还在上下文里。
- **铁律**：**同一个 path 绝不在一条表达式里既开 'w' 又读**。要转码就分两步：
  ```python
  s = io.open(p, encoding='utf-8').read()          # 先读完
  io.open(p, 'w', encoding='utf-8-sig', newline='').write(s)   # 再写
  ```
  更好的做法：**直接用 Edit/Write 工具**（它们不截断未读的文件）。
- **为什么值得记**：这类错**无声**、且一次毁两个文件；而当时我手上没有备份
  （`_backup/` 是这轮才建的）—— 正是第一节「先备份」那条铁律的现场证明。

### L. `Get-Content -Raw` 没指定编码 → config.json 从来没被读进来过（潜伏很久）★

- **症状**：新写的 `preflight.ps1` 一读 `config.json` 就 `ConvertFrom-Json : Invalid object passed in`
  并打出一屏乱码（`"涓€绉掓柊鏉愭枡瀹堕グ"`）。
- **真相**：PowerShell 5.1 的 `Get-Content` **默认按 ANSI/GBK 读**，而 `config.json` 是 **UTF-8 无 BOM**
  → 中文注释变乱码 → JSON 解析直接抛异常。**必须显式 `-Encoding UTF8`**。
- **更严重的连带发现**：`resolve_env.ps1` 里读 config.json 是**同样的写法**，而且包在 `try { } catch { }`
  里**静默吞掉异常** —— 也就是说 **config.json 一直没被真正解析过**。
  一直没暴露是因为：它的值大多是空串、`default_port` 又恰好等于代码里的兜底值 9228。
  → 已修：加 `-Encoding UTF8`，并把 `catch` 改成 `Write-Warning`（**解析失败不再静默**）。
- **教训**：
  ① 凡读写文本配置，**编码显式指定**（PS 5.1 尤其）；
  ② **空的 catch 是 bug 的温床** —— 至少要 warning；
  ③ 「本来就是好的」可能只是**默认值恰好等于期望值**。

### M. 把「看不到控件」直接写成「机制未摸清/已知缺口」（参考价，潜伏到换类目才爆）

- **症状**：`SKILL.md` / `HANDOVER.md` / `playbook.md` / `RECON.md` 四份文档都写着
  「**参考价填不进去 · 已知缺口（未实现）· 机制未摸清 → 请在后台人工确认**」。
- **真相**（2026-10-09 墙纸类目实测）：参考价**根本不是「填不进去」** ——
  它是 `[attr-field-id="参考价"]` 行里一个**默认关闭的开关**（`button.ecom-g-switch[role=switch]`）。
  **关着整组不渲染**，所以① 页面上没有 input 可填（第一次侦察的观察没错）、
  ② 必填项进度 100%、报错 `[]`（行为也没错）。错的是**把它当成了缺陷**。
  拨开后立刻长出 `*参考价凭证` + `*参考价设置` 两个 ★ 字段 —— 机制一清二楚。
- **代价**：这条假待办**每上一单就留一个说不清的窟窿** —— 交接文档让下一个人「人工确认」，
  而人工确认既没有判据也没有终点。**比不写更糟：它把「没查」伪装成「查过了，是平台的坑」。**
- **教训**：
  ① 观测到「找不到控件」时，**先问是不是「控件不在这个状态里」**（开关/联动/条件渲染），
     再决定要不要记成缺陷 —— 尤其当**模板给了字段、页面却不卡必填**时，那几乎一定是条件渲染；
  ② 文档里的「已知缺口」必须带**可执行的下一步**（找谁、看哪、判据是什么）。
     只能写「请人工确认」的，说明**还没查完**，应该记成「待侦察」而不是「待处理」；
  ③ 反面价值：`模板的 ★ ≠ 表单的必填`。参考价是**条件必填**（开关不开，金额框不存在），
     所以「必填项进度 100%」和「模板标 ★」可以同时成立 —— **判据永远以表单读回为准**；
  ④ **可选功能的收尾不是「机制查清」，而是「用户给一个默认值」**。
     机制查清后这条仍是「每次要不要问」的开放问题，直到用户当场拍板
     「参考价不开不就好了，不用填了」（2026-10-09）才真正关掉。
     → 遇到可选功能，**先问「要不要用」，再决定要不要啃机制**；两件都做时，顺序别反。

### N. 「图沿多维变化」时会**静默丢掉大半规格图**（ZDT-003 · 靠实测才发现平台只允许一值一图）

- **症状**：ZDT-003（24 张图按「颜色×尺寸」出）⑧ 失败，`spec_values_not_clickable_in_drawer`。
  逐行看 `assign[]`：**每 4 行只有第 1 行成功**（i=0,4,8,12,16,20 全对），
  其余行 `clickedAny:false` + `missed:['X色-2片']`，**重跑 3 轮现象一模一样**（说明不是抖动）。
- **根因**：抽屉的规格值下拉里，**已被别的图占用的值会消失** —— 平台支持「一张图 → 多个值」，
  不支持「一个值 → 多张图」。所以 24 张图抢 18 个值，最多只能用 18 张；同色 4 张图争 3 个值时只剩第 1 张能用。
- **差点犯的错**：第一版改动是「投影到 dims[0]、每张图挂上共现的那些值」——
  结果 24 张图全都声明要同一批值，**必然撞死**。是「跑一遍看 `assign[]` 明细」把这个假设打掉的
  （光看 `fails=['spec_images']` 只会以为又是出图组掷硬币的老毛病）。
- **修法**：`build_product.py` 里改成「**每个值只留给它遇到的第一张图**」，并把用不上的图
  **响亮打印** + 写进 `product.json.spec_image_note.dropped`（交付时要能回答「那 18 张去哪了」）。
- **教训**：
  ① 失败信息里**最值钱的是逐行明细**（`assign[]`），不是汇总那一行；
     先看「成功的行有什么共同点」——这里共同点是「每色的第 1 张」，规律直接指向根因。
  ② **平台约束要以「复现一致性」判定，别以单轮现象判定**：3 轮完全一致 ⇒ 结构性约束，不是抖动。
  ③ 数据到了平台能承载的上限，**取舍必须交给用户**（这是买家能看见的东西），
     工具要做的是「提前算出来 + 报清楚」，而不是自己挑一张了事。

### O. 兜底写在「早退守卫」之后 = 死代码，而文档偏偏按兜底写（run_listing「自动新开页」）

- **症状**：Chrome 里没有抖店标签页时，`run_until_green.ps1` 直接
  `FATAL: no_douyin_page`，**一秒都没进流程**。而 Troubleshooting 明写着
  「`no_douyin_page` → run_listing.js 会自动新开创建页」。
- **真相**：`run_listing.js` 里 `if (!probe.hasDouyin) throw ...` **排在** `connectShop` 之前，
  而「新开创建页」的兜底（`if (!page) openCreatePage(browser)`）在后面 —— 早退守卫把兜底变成了死代码。
  （兜底本身是好的：`connectShop` 在无抖店页时正常返回 `page: null`，`openCreatePage` 复用已登录 profile 新开。）
- **修法**：无抖店页时**只记一行日志、继续往下**，把「能不能新开」交给兜底判断；
  真开不出来（未登录）才退出并提示用户自己登。
- **教训**：
  ① **守卫的位置和它的条件一样重要** —— 早退守卫夹在「兜底」和「兜底要处理的情况」之间，
     就会让兜底永远跑不到；改代码时先问「这条 throw 之后还有没有代码是为这个 case 写的」。
  ② 文档承诺的行为**要有对应的实测**：这句「会自动新开」写了好几天没人验，
     因为平时浏览器里总有抖店页；**只有把标签页关掉才暴露**。
     想到这种「平时不触发」的分支，就该顺手制造条件验一次。
  ③ 报错要指出**下一步动作**：这次一句 `no_douyin_page` + 文档说会自动开，等于把人引到错的方向。

### P. 模板 R5 的残留会**冒充我们的数据**（材质差点被旧值顶替）

- **症状**：MZB-001 灌数据后，成品「抖音」sheet 的 `★ 材质` = **聚脂钎维** ——
  这不是我写的值（我根本没映射到材质），是**模板里上一条链接的残留**。
  build 报告同时出现 `参考价 = 100.0`，也是残留（`参考价设置=100`）被 `build_product` 读进去了。
- **根因**：`fill_dy_template.py` 只写「商品标识/标题/属性/SKU 列」，**其它列原样继承模板**。
  于是：残留列里若有 ★必填属性，就会以「成品数据」的样子出现在交付物里；
  而 build 会读其中一部分（`参考价设置` → `ref_price`）。
  这次的触发条件是「源列名是**主体材质**，而 `ATTR_ALIAS` 只有**表面材质**系」→ 材质没被写入 → 残留留了下来。
- **修法**（两处）：
  ① `ATTR_ALIAS` 补 `主体材质 → 材质`（猫抓布素材包 16 个商品的源列名都是它）；
  ② `fill_dy_template.py` 增加**残留守卫**：写完 row 5 后，把「我们没写却非空」的列列出来
     （实测猫抓板模板报出 10 处：主图/商品详情/参考价设置=100/售后政策…）。
     **这条 guard 的价值在反证**：修好材质后再跑，`材质` 不再出现在残留清单里。
- **教训**：
  ① **「模板是从真实链接导出的」这件事必须当成前提**：交付前抽查 row 5，
     确认「出现的列 = 我们打算写的列 + 已知占位（主图/详情图）」。
  ② 属性没映射上，**症状不一定是「报错」**，而是「静默沿用旧值」—— 比报错更危险。
  ③ 别把「上一条链接的值」当默认：这正是门禁 41/43 的同一个病根（`材质` 又一次是反例）。

### Q. 用编辑工具改 `.ps1` 会**悄悄剥掉 BOM**（2026-10-10 又踩一次）

- **症状**：只改了 `resolve_env.ps1` 里三行（playwright-core 解析链），逻辑没问题，但 BOM 没了。
  PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK 读 → 中文串全烂（本机 dot-source 看着正常，
  是因为当前会话是 PS 7；**目标环境是 PS 5.1**）。
- **根因**：`Edit` / `Write` 这类工具写文件默认**不带 BOM**。事故 34 早就写了「`.ps1` 必须 UTF-8 带 BOM」，
  但那条只写了「改完记得补」，**没做成机械检查**，于是隔几天又踩。
- **修法（已机械化，别靠记性）**：`scripts/selftest.ps1` 第 1 项就是逐文件检查 BOM，
  `package.json` 式的「记得做」改成了「一条命令验」。手动补：

```powershell
# 查
Get-ChildItem "<skillRoot>\scripts\*.ps1" | ForEach-Object {
  $b = [System.IO.File]::ReadAllBytes($_.FullName)[0..2]
  "$($_.Name): BOM=" + ($b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)
}
# 补（python 一行）
python -c "import glob;p=glob.glob(r'<skillRoot>\scripts\*.ps1');[open(f,'wb').write(b'\xef\xbb\xbf'+open(f,'rb').read()) for f in p if not open(f,'rb').read().startswith(b'\xef\xbb\xbf')]"
```

- **教训**：**凡是「改完必须做」的动作，要么进 `selftest.ps1`，要么进 preflight —— 不要写进文档当守则。**
  这条规矩自己就是例子：写在文档里的版本连续两次失效，写成脚本检查后当场抓到。

### R. 「编辑工具剥 BOM」之外，这轮审计还抓出「上游没跟上」

- **症状**：把 playwright-core 收进技能自带（`tools\npm` + `pwresolver.js`）之后，
  `preflight.ps1` 仍在用 `require.resolve('playwright-core')` 判依赖 ——
  这个判据只认机器级 `node_modules`，**只有自带副本的机器会被误判 FAIL**（修了下游、漏了上游）。
- **同类**：`run_listing.js` 端口写死 `'9228'`，而文档说「默认取 config.json 的 default_port」；
  `run_until_green.ps1` 设了 `DY_ATTEMPT` 却没人读（死变量）。
- **修法**：`preflight` 改调 `scripts\which_pw.js`（同一个解析入口）；`run_listing.js` 读 config；
  `DY_ATTEMPT` 进日志；`DY_STOP_AFTER` 传非法值**直接报错**（以前静默跑完全程）。
- **教训**：改一个「共用能力」（依赖解析、端口、路径）时，**顺手 grep 一遍还有谁自己实现了一份**。
  并发改动时更要注意：本轮两个审计 agent 的结论里就有「审计期间代码被改写」的偏差。

## 四、环境类坑（跟代码无关，但会白费一轮）

| 坑 | 现象 | 处理 |
|---|---|---|
| PowerShell 重定向写文件是 **UTF-16** | `Tee-Object`/`>` 写出的 .log 用 utf-8 读会 `UnicodeDecodeError` | 用 `[System.IO.File]::WriteAllText($p, $s, (New-Object System.Text.UTF8Encoding($false)))` |
| `.ps1` 必须存 **UTF-8 带 BOM** | PowerShell 5.1 按 GBK 读，中文串被打乱 → 报一堆「意外的标记」 | 改完 `.ps1` 补 BOM（`io.open(p,'w',encoding='utf-8-sig')`） |
| PowerShell 双引号 here-string 会展开 `$变量` | 文档里的 `$DyEnv` 被替换成空串 | 用单引号 `@'...'@`，或别用 here-string 写文件 |
| `& $py -c @'...'@` 里的双引号被吃掉 | `SyntaxError: invalid syntax`（`r"C:\..."` 变成 `rC:\...`） | **把 python 写进临时 .py 再执行** |
| 标签页 CDP 卡死 | `connectOverCDP` 挂在 `ws connected` / `Timeout 120000ms exceeded`；常见是**别的站点**的页（如拼多多推广页） | 手动再跑一次 `flow.closeHungTabs(port)`（返回 `{closed:[...]}` 告诉你是谁）。**别 taskkill Chrome**（丢登录态） |
| 临时目录的文件会被系统清掉 | 手写的扫描脚本第二天不见了（我为此重写了一次） | 常用工具要**落进技能目录**（如 `tests/verify_sku_table.js`），别只放 `%TEMP%`。**也别把临时产物当资产写进文档** —— `RECON.md §8` 曾把首次侦察的 11 个 dump（`create_recon.json` / `dy_attrs.js` / `sku_test.xlsx` …）列成「已产出」，其实早被清掉，2026-10-09 才发现并改成「历史产物」 |
| 素材路径含 WPS 的 Unicode 空格（`\u2005`） | 手拼路径找不到目录 | 用 python `os.listdir` 逐级探测，或 `Get-ChildItem -LiteralPath` |
| **PS 5.1 读 UTF-8 无 BOM 文本默认按 GBK** | 中文变乱码、`ConvertFrom-Json` 抛 `Invalid object passed in` | **显式 `Get-Content -Raw -Encoding UTF8`**（或 `[System.IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)`）。详见事故 L |
| 一行 python 里既开 `'w'` 又 `.read()` 同一路径 | 文件被截断成 0 字节（自我截断） | 分两步：先读完再写；或直接用 Edit/Write 工具。详见事故 K |
