## 一、整体流程：两步

| 步骤 | URL | 内容 |
|---|---|---|
| 第一步 | `https://fxg.jinritemai.com/ffa/g/create` | 主图 5 张 + 商品标题 + 商品类目 → **下一步** |
| 第二步 | 同 URL（`?` 后缀，同页渲染） | 类目属性 / 图文信息 / 价格库存 / 服务与履约 / 其他信息 |

> 页面是**智能识别**流程：传主图 + 标题后，抖店 AI 会预填商品类目和标题推荐。
> ⚠️ AI 标题推荐**不可用**（实测推的是「法定货币央行发行纪念币…」完全无关），必须用数据包标题。

## 二、第一步（基础三件套）

### 2.1 主图上传（5 个槽位）

| 槽位 | 说明 | file input |
|---|---|---|
| 商品正面图 | **必填**，≥600×600px | `input[type=file]` nth(0)，accept=`image/*` |
| 上传辅助图 ×4 | 选填 | nth(1..4) |

- 全部 `input[type=file][accept="image/*"]`，**offsetParent=false**（隐藏 input，setInputFiles 可用）
- 「*主图 发布≥3张优质图片（建议上传5张）」
- 拼多多的 10 张轮播 → 抖店只有 **5 张**，多的要舍弃

### 2.2 商品标题

```js
// ⚠️ 不要写死 placeholder 数字：全新第一步是 2-60个字符（1-30个汉字）、有草稿/第二步是 15-60个字符（8-30个汉字）
//    正确找法：遍历 input，取 placeholder 同时含「个字符」与「汉字」的那个（setTitle 已按此实现）
page.locator('input.ecom-g-input[placeholder*="个字符"]')
```

- 限制：**15-60 字符 / 8-30 汉字**（汉字按 2 字符计）
- GPVC-001 标题 28 汉字 → 显示 `58/60`，**几乎顶格，加字会超**

### 2.3 商品类目

两种方式：
1. **AI 推荐**：主图+标题传完后自动给出候选（实测给的是 `家装建材 > 墙面材料 > 墙纸`）+「更多推荐」
2. **手动选择类目**（点 `text=手动选择类目`）→ 弹窗

弹窗结构（`ecom-g-modal-root` / `styles_modalWrapper__CPYeq`）：

| 元素 | 选择器 |
|---|---|
| 主搜索框 | `input[placeholder*="类目关键词搜索"]`（cls `style_searchInput__AXVqd`） |
| 一级类目搜索 | `input[placeholder="搜索一级类目"]` |
| 搜索结果列表 | `div.style_resultList__qTh9w` |
| **单个搜索结果** | `div[class*=resultItem]`（cls `style_resultItem__m_ro6`），文本是**拼接无分隔**的完整路径，如 `家装建材墙面材料墙纸` |
| 已选 | 弹窗底部「已选 家装建材墙面材料墙纸」 |
| 确认 / 取消 | `button:has-text("确认")` / 取消 |
| 智能推荐区 | `家装建材 > ... > 墙纸`、`居家日用 > ... > 装饰贴/冰箱贴/墙贴/瓷砖/玻璃贴`、`家装建材 > ... > 墙布/壁布`、`家装建材 > ... > 墙咔/柔性墙板` |

**关键坑（实测）**：
- 用 Playwright `click()` 点搜索结果**会被浮层拦截**：
  `div.ant-scrolling-effect#__ffa-goods-popup-container__` 的子树 `intercepts pointer events`。
- **解法：用原生 `el.click()`（evaluate 内）绕过指针拦截**，可行。
- 点完必须再点弹窗「确认」，之后主表单的 `商品类目` 才落值，`下一步` 才会从 disabled 变 enabled。

#### 实测：识别效果（2026-09-30，GPVC-001 / 16 SKU）

上传一个 5 列表格的 xlsx（表头 `颜色 | 款式 | 售卖价 | 库存 | 规格编码`，16 行数据），点「智能识别」：

进度文案依次出现：`正在获取您上传的内容` → `已识别完成您上传的信息` → `已为您生成规格信息` → `正在为您优化规格层级`
完成后助手区变为：`完成识别并填入规格选项、价格库存` + 「删除」按钮

生成的规格表：
```
表头：颜色 | 款式 | * 价格 | * 现货库存 | SKUID | 商家编码 | 条形码 | 预览图 | SKU状态
```

| 识别结果 | 实测值 |
|---|---|
| 规格1（颜色） | 8 个值全部识别：`【真格栅】人气JH207温馨色` … `【真格栅】极简JH423米灰色`（placeholder `请输入颜色`） |
| 规格2（款式） | 2 个值全部识别：`【试看品质】1片 25x50cm`、`【基础规格】12片装 约1.5平米`（placeholder `请输入款式`） |
| 价格列 | 9.9 / 45.9（来自 Excel「售卖价」，placeholder `请输入`） |
| 现货库存列 | 10000（来自「库存」，placeholder `请输入库存`） |
| 商家编码列 | `50cm格栅JH207-25X50cm-1片` 等（来自「规格编码」，placeholder `请输入erp编码`） |
| 条形码列 | 空（Excel 没有该列） |
| 汇总价格区间 | 自动算出 `9.9~45.9` 填入「售卖价」框 |

**结论**：助手能按表头语义自动映射（售卖价→价格、库存→现货库存、规格编码→商家编码），并自动建规格1/规格2 与全部 SKU 行。
→ **大批量（如 GPE-002 的 270 SKU）不必逐格 setter，生成 Excel 上传即可**，比拼多多快得多、更可靠。

## 四、与拼多多（pdd-product-listing）的关键差异

| 维度 | 拼多多 | 抖店 |
|---|---|---|
| 流程 | 类目页 → 表单（1 步） | **第一步(主图+标题+类目) → 第二步(全表单)** |
| 主图 | 轮播 10 张 | **正面图 1 + 辅助图 4 = 5 张** |
| 标题 | ≤30 汉字 | **8-30 汉字 / 15-60 字符**（汉字算 2） |
| 类目 | 搜索 + 全路径精确匹配 | **AI 推荐 + 手动弹窗搜索（结果文本无分隔符）** |
| 类目属性 | 「墙贴」属性集 | **「墙纸」属性集（14 重要 + 7 其他），字段名完全不同** |
| 规格/SKU | 逐行 setter（虚拟滚动 + sticky） | **可走 Excel 智能填写助手** |
| 详情图 | ≤50 张 | ≤50 张，**额外要求宽 620-1290px** |
| 价格 | 拼单价 / 单买价 / 参考价 | **售卖价 / 参考价**（无「拼单价」概念） |
| 必填 | 错误计数 | **填写检查 + 必填项进度 + 商品信息质量分** |
| 提交 | `goods_add/success` | `发布商品`（本次不提交） |

### 6.2 预览图规则：已确认

**结论：抖店的 SKU 图是「规格图」，挂在规格值上，不是逐 SKU 行。**

流程（点「批量上传规格图」）：
1. 直接唤起文件选择器（**无弹窗**）
2. 上传后打开抽屉 **「规格图设置」**，提示「请将已上传的规格图与规格值相匹配」
3. 抽屉表格：`规格图 | 规格值 | 操作`，**每张图一行，行序＝上传顺序**（已用文件字节数核对：94310/121302/…/444066 与 sku_01…sku_08 一一对应）
4. 每行的规格值下拉 `div.ecom-g-select-dropdown.sp-multiple-dropdown`，**多选**，选项就是该商品的规格值（8 个颜色）；留空＝「未选择默认生成新规格」
5. 点「确定」落库

**实测**：8 张按颜色顺序上传 → 逐行指定对应颜色 → 确定 → 抽屉关闭；规格值旁出现 98×98 缩略图。
另有「添加规格图」按钮可在抽屉内追加图片。

> ⚠️ **反向不成立：一个规格值只能挂一张图**（2026-10-09 ZDT-003 实测）。
> 抽屉支持「一张图 → 多个值」，但某个值被一张图占用后，**会从其它行的下拉里消失**
> （下拉能打开、值就是不在里面 → `clickedAny=false`，重试 3 轮现象一致）。
> 所以图沿多维变化时（24 张「颜色×尺寸」图 vs 18 个「色-片数」值）只能用得上其中一部分。
> `build_product.py` 会投影到 dims[0]、每值只留一张图，并把用不上的图报出来（见 SKILL.md 硬约束 4）。

> **默认口径（用户 2026-10-09 定：「只挂颜色规格图就好了吧」）**：**只挂「颜色」那一维** ——
> 即投影到 `dims[0]`，**不逐条发问**；只有用户要换挂法时才问。
> ZDT-003 落到的就是这句：`dims[0]` = `颜色-片数`，每色 3 个片数值共享该色一张图（6 张图管 18 个值）。

**映射策略**：图片按**规格值顺序**上传即可让行序与规格值一一对应，无需文件名匹配。

> 与拼多多的差异：拼多多是**逐 SKU 行**传预览图（72 行就传 72 次）；抖店是**按规格值**传（GPVC-001 只要 8 张），且 SKU 表另有「预览图」列。
> Excel 模板里的 `规格图片文件名` 列（`skuRole: specImage`）对应的就是这里的规格图。

### 6.5 参考价：已确认是「默认关闭的开关」（2026-10-09 墙纸类目 · 可逆实验）

**结论先说：参考价不是「邻近没有 input」，而是一个默认关的开关 —— 关着整组不渲染，
所以既不卡必填、也没有 input 可填。** 流程默认不碰它是对的。

定位（稳定选择器）：`[attr-field-id="参考价"]`。

| 状态 | 行内结构 | 必填 |
|---|---|---|
| **关**（默认） | 行 = 标签 + `button.ecom-g-switch`（`role="switch"`、`aria-checked="false"`、`dropdownclassname="auto-dropdown-id-参考价"`）。**行内 `input` 数 = 0**，标签**无 `*`** | `必填项进度 100%`，报错 `[]` |
| **开** | 行内长出灰底容器 `styles_contentBox`，含两个**带 ★** 的字段 | —— |

打开后的两个字段（原文）：

| 字段 | 控件 | 说明 |
|---|---|---|
| `*参考价凭证` | radio ×3：`厂商建议零售价` / `吊牌价` / `官网零售价`（`input[type=radio]` value = 1 / 2 / 4）+ `上传凭证图`（`input[type=file]`） | 凭证图是该商品专属素材，源素材包里通常没有 |
| `*参考价设置` | `input`（文本），placeholder 原文「**参考价需大于等于售卖价，最多保留2位小数**」 | 即模板里的 `reference_price` |

页面提示原文：**「请确保录入的价格真实有效并与价格凭证保持一致。若价格录入错误或上传虚假凭证，
您将面临价格欺诈等法律风险。当前参考价主要场景为直播间讲解展示使用，未来将应用在商品详情、搜索等场景。」**

**与模板 R4 的对应**（解释了那个 ★ 为什么在表单上不成立）：

| 模板列 | 字段 | key | 模板标记 | 表单实际 |
|---|---|---|---|---|
| AI | 参考价设置 | `reference_price` | ★ | 金额输入框 —— **只在开关打开后才存在** |
| AJ | 参考价凭证类型 | `reference_price_certificate_type` | 否 | 开关打开后的 radio（3 选项，与「选项_dy」一致） |
| AK | 参考价凭证图 | `reference_price_certificate_urls` | 否 | 开关打开后的 file input |
| AL | 参考价 | `reference_price_enable` | 否 | **就是那个开关本体** |

→ 模板的 ★ 是**条件必填**（「IF 开参考价 THEN 金额必填」），不是「无条件必填」。
**教训：模板的 ★ 不能直接当表单必填用，一律以表单读回（必填项进度 + 填写检查报错）为准。**

**实验方法**（`tests/reveal_reference_price.js`，可逆）：
读状态 → `el.click()` 开关 → 再读（行结构整体变样）→ 再点一次归位。
注意：拨开后用「文本 == 参考价 且含 switch」这种选择器会**失效**（行里多了 contentBox），
必须用 `attr-field-id`；实验记录见 `tests\_archive\_reveal_ref_off.txt` / `_reveal_ref_on.txt` / `_reveal_ref_back.txt`。

**用户拍板的默认值（2026-10-09）**：「参考价不开不就好了，不用填了」→
**整组不动、不必为它逐条发问**。只有用户主动要求开某条链接时才问「凭证类型 + 凭证图 + 金额（≥售卖价）」。
